─── 3. CARACTÉRISTIQUES TECHNIQUES DU FLUX ────────────────────────────

  • Encodage          : UTF-8 (déclaré en minuscules dans l'en-tête)
  • Format balises    : minuscules, sans accent
  • Booléens          : O / N (jamais true/false ni 1/0)
  • Dates             : jj/mm/aaaa (sans horodatage)
  • CDATA             : appliqué sur tout champ texte libre
  • Mode fichier      : Annule/Remplace — toutes les annonces actives
                        sont incluses dans chaque flux
  • Statuts exportés  : publiee, active, en_ligne uniquement
                        (jamais brouillon)

Points de conformité spécifiques incluant :

  ✓ Mention Géorisques obligatoire dans chaque <texte>
    ("Les informations sur les risques auxquels ce bien est exposé
     sont disponibles sur le site Géorisques : www.georisques.gouv.fr")

  ✓ <honoraires_payeurs> (acquereur/vendeur/acquereur et vendeur)
    — obligation ALUR

  ✓ <alur_pourcentage_honoraires_ttc> pour les ventes

  ✓ <url_tarifs_publics> (barème honoraires) — obligation arrêté
    10/01/2017

  ✓ DPE complet : étiquette conso, valeur conso, étiquette GES,
    valeur GES, date de réalisation, version, fourchette dépenses
    énergies min/max, date indice prix

  ✓ <zone_georisque> et <obligation_debroussaillement>

  ✓ Copropriété : <copropriete>, <alur_nb_lots>,
    <charges_copropriete_annuelle>, <alur_syndic_en_procedure>

  ✓ Location : <modalite_recuperation_charges_locatives> (sans "s"),
    <depot_garantie>, <honoraires_location>,
    <honoraires_etat_des_lieux>, <duree_du_bail>,
    <zone_encadrement_loyer>

  ✓ Minimum 3 photos par annonce (URLs HTTPS fictives dans ce test —
    elles seront remplacées par les vraies URLs en production)


─── 4. WORKFLOW DE DIFFUSION PRÉVU ────────────────────────────────────

Une fois que vous aurez validé ces fichiers et transmis les accès FTP,
notre système :

  1. Génère automatiquement les 5 XML chaque jour à 19h00
  2. Les emballe dans des ZIP [login_ftp].zip (format 32 bits)
  3. Dépose chaque ZIP sur ftp.ubiflow.net via FTP passif
  4. Trace chaque dépôt dans une table de log avec horodatage,
     MD5, nombre d'annonces, statut
  5. Application de garde anti-doublons : si un ZIP a exactement
     le même MD5 qu'un dépôt réussi des 24 dernières heures, le
     nouveau dépôt est automatiquement ignoré pour éviter la
     surcharge inutile
